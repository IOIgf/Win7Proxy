# Win7Proxy — Windows 7 代理客户端

一个能在 **Windows 7 SP1 (x64)** 上运行的代理客户端，默认使用 **Xray-core（官方 `-win7` 构建）**，
支持导入 **v2rayN / Clash / SIP008** 三种订阅，覆盖 VMess、VLESS(+XTLS/REALITY)、Trojan、
Shadowsocks/SS2022、Socks、HTTP、Hysteria2 等主流协议。流量接管方式为 **系统代理 + 内核路由分流**（无驱动、无 TUN）：
系统代理指向本机内核端口，由内核按 geoip/geosite 规则把国内/私有网段直连、其余走代理。
Windows 10/11 还可切换 V2Ray 或 sing-box，以运行 Xray 已移除的 h2 等传输；这两个内核没有 Win7 官方构建。
**Hysteria2 由 Xray 与 sing-box 支持**（V2Ray 不支持）；Xray 官方的 Win7 构建同样包含 Hysteria 2，
因此 Win7 上也能用，只需把内核更新到支持该协议的版本（官方 v26.3.27 起，用「更新内核」即可拉到最新版）。

当前版本：**v1.5.3**

## 一、前置条件（一次性的）

1. **Windows 7 SP1 x64**。
2. 安装 **.NET Framework 4.6.1 及以上**（本项目编译目标为 `net461`，已装的 4.6.1 可直接运行；
   Win7 最高支持到 **4.8**，**4.8.1 起仅支持 Win10/11**，请勿在 Win7 上装 4.8.1）。
   若尚无任何 .NET Framework，到 https://dotnet.microsoft.com/download/dotnet-framework/net48
   下载 4.8 离线安装包（Win7 可用）。
3. 建议安装 Windows 更新补丁 **KB4474419 / KB4490628**（让老系统正确支持 TLS 1.2，
   否则 https 订阅可能拉取失败）。

## 二、首次运行

1. 解压 `Win7Proxy-v1.5.3.zip` 到任意目录（路径不要含中文/空格最佳）。
2. 内核已随包提供：`core\xray.exe` 与 `core\geoip.dat` / `core\geosite.dat` 解压即用。
   仅当要**更新**内核时，再运行 `fetch-core.bat` 拉取最新 xray-win7（内置多个 GitHub 镜像，逐个尝试）。
3. 双击 `Win7Proxy.exe`。

## 三、使用

- **导入订阅**：工具栏「导入订阅」或菜单「订阅 → 导入订阅」→ 填写订阅 URL 与名称 → 拉取。支持：
  - v2rayN 订阅（base64 包裹的 vmess/vless/trojan/ss 链接）
  - Clash / mihomo 订阅（YAML `proxies:` 列表，含 `reality-opts` / `grpc-opts` / `h2-opts`）
  - SIP008（Shadowsocks 官方 JSON）
  - 格式可自动识别，也可在对话框里手动指定。
  - 若订阅站点使用自签名证书，勾选「跳过 TLS 证书校验」。**该项只对这一次请求生效**，
    程序默认严格校验证书，不会全局关闭验证。
  - **重复导入同一个 URL 会替换旧订阅的节点**，不会越积越多。
- **从剪贴板导入**：菜单「订阅 → 从剪贴板导入」，单条链接或整份订阅文本都可以。
- **按订阅分组查看**：节点列表按订阅分段显示，每个订阅（以及「手动」）各有一行分组标题，
  点标题即可折叠/展开该组，各订阅的节点不再全堆在一起。工具栏「订阅」下拉还能只看
  「全部 / 某个订阅 / 手动」。订阅删除或改名后分组会自动跟上。
- **更新订阅**：工具栏「更新订阅」会重新拉取所有订阅；「订阅 → 订阅管理」可单独
  更新 / 编辑 / 删除某个订阅（删除订阅会连带删除它带来的节点）。更新时会尽量把已测得的延迟继承下来。
- **添加节点**：菜单「节点 → 添加节点」，粘贴单条 `vmess://` / `vless://` / `trojan://` / `ss://` / `hysteria2://` 链接。
- **复制原始链接**：选中节点后「节点 → 复制原始链接」，把分享链接放回剪贴板。
- **去重 / 清空延迟**：菜单「节点 → 去除重复节点 / 清空延迟结果」。
- **测试延迟**：在节点列表里**按住 Ctrl 逐个点选、或 Shift 框选**多个节点，再点「测试延迟」即可批量测延迟
  （点「全选」可一键选中全部；不选任何行则测全部）。
  - **VMess / VLESS / Trojan / SS 等 TCP 类节点**：最多 16 并发，按 `Address:Port` 的 TCP 连通性计时；
    这是**到节点服务器的 TCP 往返时延**，不是"打开网页的体感速度"，只适合横向比较节点。
  - **Hysteria2 等 UDP/QUIC 节点**：hy2 跑在 QUIC/UDP 上、并不在节点端口监听 TCP，用 TCP 去连只会得到假的「超时」。
    这类节点改用**真实延迟测试**：临时用当前内核拉起一个本地入站，实际发一次 HTTP 请求再计时，
    结果反映"能不能真连上以及耗时"。因为每个节点都要临时起一次内核，是**逐个顺序执行**，比 TCP 测试慢很多。
- **批量删除**：选中多个节点后点「删除选中」可一次移除（会二次确认）。
- **按列排序**：点击表头按该列排序（再点一次切换升/降序）。延迟列按数值排序，
  未测（`-`）的排到最后。刷新列表会保持滚动位置和选中项。
- **选择节点 + 启动**：单击选中一个节点（上方「当前节点」会显示是谁），选好模式后点「启动」；
  **双击某一行可直接以该节点启动**；换节点就选另一个再点「启动」（会先停旧内核再起新的）。
  - 模式「全局」：所有流量走代理。
  - 模式「规则」：国内/私有网段直连，其余走代理（geoip/geosite 自动分流，无需 PAC 文件）。
    规则模式下额外配置国内 DNS，避免域名被污染成境外 IP 后误判为需要代理。
  - 模式「直连」：停止本程序接管并恢复原系统代理设置，**不启动内核**。
  - **运行中切换模式会立即重建配置并重启内核**，不用再手动点一次「启动」。
- **停止**：点「停止」结束内核并恢复程序接管前的系统代理/PAC 设置。
  内核若自行崩溃退出，程序也会自动恢复；下次启动还会处理异常退出遗留的代理设置。
- **托盘**：右下角托盘图标可「启动 / 停止 / 显示窗口 / 退出」。
- **设置**：菜单「设置」里可开启**开机自动启动**、**启动时自动连接上次节点**、**导入订阅时自动去重**。
- **更新内核**：工具栏「更新内核」在后台下载当前选择的内核和规则数据；运行中更新会安全停止并在成功后重连。

## 四、配置文件

- 订阅与节点、当前选择、模式与偏好设置保存在 `%AppData%\Win7Proxy\app.json`，采用原子写入并保留 `app.json.bak`；主文件损坏时会自动从备份恢复。
- 运行期生成的内核配置在 `core\config.json`；Xray/V2Ray 日志为 `access.log` / `error.log`，sing-box 日志为 `sing-box.log`。
- 内核进程 PID 记录在 `core\xray.pid`，用于清理上次异常退出残留的进程。

## 五、排错

- **启动报“找不到 xray.exe”**：按第二节放置内核，或运行 `fetch-core.bat`。
- **订阅拉取失败 / TLS 错误**：安装 KB4474419/KB4490628；若站点是自签名证书，
  在导入对话框勾选「跳过 TLS 证书校验」。
- **系统代理未生效**：确认浏览器使用“使用系统代理”。修改模式或节点后建议重启浏览器，
  让它重新读取系统代理设置。
- **端口被占用**：若启动时日志提示 10808 端口已被占用，说明有另一个代理软件在跑，
  先退出它再启动。
- **无法访问内网/局域网**：私有网段默认直连（同时写进了系统代理的绕过列表），一般无需处理。

## 六、从源码构建（开发者）

在 Windows 上用 Visual Studio 2019/2022 打开 `Win7Proxy.sln` 直接生成即可。
也可用 .NET 8 SDK 编译（编译目标为 `net461`，兼容 Win7 的 .NET 4.6.1+）：

```
dotnet build Win7Proxy/Win7Proxy.csproj -c Release -f net461
```

（需 `Microsoft.NETFramework.ReferenceAssemblies.net461` 提供 net461 引用程序集；
`ProxyCore` 同时多目标 `net461;net8.0`，被 GUI 引用时取 net461。）

逻辑层 `ProxyCore` 的单元测试：

```
dotnet test ProxyCore.Tests/ProxyCore.Tests.csproj
```

Linux/macOS 上可用 `./pack.sh [程序版本号] [Xray 版本号]` 构建并打包
（两个参数都可省略：版本号只影响产物文件名，Xray 版本号省略时自动查 latest；
脚本假定 .NET SDK 在 `./.dotnet/dotnet`）。

### 自动构建与发布

仓库已配置 GitHub Actions（`.github/workflows/build.yml`）：推送 `main`、发起 PR 或手动触发时，
  会先跑单元测试，再在 Linux runner 上构建 `net461` Release，下载 xray-win7 内核与 geo 数据
（多镜像兜底），打包成 `Win7Proxy-<版本号>.zip` 上传为构件；
打 `v*` 标签（如 `v1.5.3`）推送时，会自动创建 GitHub Release 并附上该 zip。

## 七、版本记录

### v1.5.3

**修复"内核报错在界面上完全看不到"**——这是排查一切连接问题的前提：

- 旧版生成的内核配置把日志写进 `core\error.log`（Xray 的 `log.error`、sing-box 的 `log.output`），
  程序日志框捕获的是进程 stdout/stderr，于是几乎一片空白；用户只能看到浏览器那句
  「连接意外终止」，真正的原因全在文件里。
- 同时日志级别是 `warning`，而 Xray 把具体的失败原因（`x509: certificate signed by unknown authority`、
  QUIC/ALPN 握手失败、认证失败等）打在 **info** 级，`warning` 只剩下毫无信息量的
  `failed to read response ... closed pipe`。
- 现在：不再重定向到文件，Xray 级别改为 `info`。**从本版起，真实失败原因会直接显示在程序日志框中。**
- 另经真实端到端验证（真实 Xray 服务端 + 官方 hysteria2 服务端）：本程序生成的 Trojan 与
  Hysteria2 配置在证书可信任（或已提供 `pinSHA256`）时均可正常连通。

### v1.5.2

修复自签名证书的 **Trojan / Hysteria2** 节点连不上（表现为浏览器「连接意外终止」）：

- **根因**：Xray 26.x 已彻底移除 `allowInsecure`，官方替代只有 `pinnedPeerCertSha256`
  （且**只接受十六进制**）。自签名证书的服务器在无法跳过校验时，TLS 握手会被内核拒绝并拆掉连接。
  Trojan / Hysteria2 恰恰是最常用自签名证书、最常依赖 `insecure=1` / `skip-cert-verify` 的协议。
- **`tls=1` / `security=1` 不再退化成明文**：旧版 `NormalizeSecurity` 只认 `"true"` 不认 `"1"`，
  于是生成 `"security": "none"`，等于用明文去连 TLS 端口，Trojan 必然失败。现在 `1`/`xtls`/`yes`/`on`
  都归一化为 `tls`，`0`/`off`/`no` 归一化为 `none`。
- **base64 的 `pinSHA256` 不再被丢弃**：Hysteria2 分享链接里的 pin 基本都是 base64，
  而 Xray 只认十六进制。旧版遇到 base64 直接返回空串，pin 静默失效；现在会自动转成十六进制
  （兼容 URL-safe 与无填充写法）。
- **Trojan / VLESS / VMess 也开始解析证书 pin**：此前只有 Hysteria2 分支读 `pinSHA256`，
  Trojan 节点即使写了 pin 也会被丢掉。现在链接与 Clash 的所有节点类型都解析
  `pinSHA256` / `pinnedPeerCertSha256` / `certSha256`。
- 提示：若日志里出现「Xray 已移除 allowInsecure…」而你手上又没有任何 pin，
  Xray 26.x 下无法跳过校验（Win7 也用不了 sing-box）。可用
  `core\xray.exe tls ping <节点域名>` 取到 `Cert's leaf SHA256:` 后，把
  `pinSHA256=<该十六进制值>` 加进节点链接再导入。

### v1.5.1

- **更新内核不再删掉可用的 geo 数据**：旧版下载前会先删除目标文件，一旦所有镜像都失败，
  原本正常的 `geoip.dat` / `geosite.dat` / `.srs` 就被删掉，规则模式随之报错，界面却仍显示"安装完成"。
  现在先下载到 `.part` 临时文件、校验通过再替换，下载结果也会明确提示。
- **修复测延迟与界面刷新的数据竞争**：测试线程原先直接按行号读写共享的界面列表，
  期间导入/删除节点或切换分组会写错行甚至抛异常。现在改为按节点引用在 UI 线程重新映射行号，
  并在 UI 线程存盘，避免"集合已被修改"。
- **Shadowsocks SIP003 插件不再被静默忽略**：sing-box 内核直接透传 `plugin` / `plugin_opts`
  （`obfs-local` / `v2ray-plugin`）；Xray / V2Ray 把 `v2ray-plugin` 的 websocket 模式等价映射为
  ws 传输（含 TLS），无法表达的 `simple-obfs` 会在启动前明确报错，而不是生成一份连不上的配置。
- **修复 Hysteria2 端口跳跃区间分隔符**：订阅里写成 `20000:30000` 时，Xray 的 `udpHop`
  现在会归一化为连字符写法（sing-box 仍用冒号）。
- **打包脚本 `pack.sh` 参数不再串用**：旧版把"程序版本号"同时当成 Xray 版本标签，
  执行 `./pack.sh v1.5.0` 会去下载不存在的 Xray 发布，产出的包没有内核与 geo 数据。
  现在两个参数分开：`./pack.sh [程序版本号] [Xray 版本号]`。
- 修补界面细节：只选中分组标题行时测延迟会给出提示而不是静默无反应；
  最小化到托盘时恢复滚动位置不再可能抛异常。
- 清理：`PacGenerator` 去掉无意义的 `pacPort` 参数、移除已废弃的 `CoreConstants.PacPort`；
  订阅 User-Agent 改用统一版本常量；CI 开发构建版本号从 `Win7Proxy.csproj` 读取。

### v1.5.0

- 新增**允许局域网访问**：工具栏「局域网」开关，打开后入站监听 `0.0.0.0`，同网段的其他设备也能使用本机代理；
  系统代理仍指向 `127.0.0.1`。开启时会提示「无认证、请确认网络可信」的安全风险。
- 新增**自定义 mixed 端口**：把原来的 SOCKS(10808) + HTTP(10809) 合并为一个 mixed 端口（同一端口同时服务
  HTTP 与 SOCKS），工具栏「端口...」可修改，默认 10808。系统代理与启动健康检查都基于该端口。
- 新增**订阅名称自动获取**：导入订阅时备注名留空，会依次从响应头 `profile-title`、
  `Content-Disposition` 文件名、URL 主机名推断；手填的名称不会被覆盖。
- 新增**节点列表按订阅分组显示**：每个订阅（以及「手动」）各有一段可折叠的分组标题行，
  点标题即可折叠/展开；工具栏「订阅」下拉仍可只看某一个分组。

### v1.4.0

- 新增**按订阅分组筛选**：工具栏「订阅」下拉可在「全部 / 某个订阅 / 手动」之间切换，
  只显示该分组的节点，不再把所有订阅的节点堆在一个列表里。订阅删除或改名后下拉会自动重建，
  当前分组不存在时回落到「全部」。「全选 / 测试延迟 / 删除选中」都只作用于当前分组。

### v1.3.2

- **修复带端口跳跃的 Hysteria2 节点导致 Xray 26.x 内核崩溃**：端口跳跃（`ports`）会生成
  `finalmask.quicParams.udpHop`，但旧版未同时输出 `interval`。Xray 26.x 在缺省 interval 时
  会把 30 秒的纳秒值再乘一次 `time.Second`，int64 溢出为负数，`hopLoop` 里的 `NewTicker`
  直接 panic 并终止内核进程。表现为「测试延迟」对这类节点报「无法连接到远程服务器」，
  且正常启动代理后首次走流量即断流。现在端口跳跃会显式带上 30 秒的 hop 间隔；
  不带端口跳跃的节点不受影响。

### v1.3.1

- **修复 Hysteria2 节点全部显示「超时」**：旧版「测试延迟」用 TCP 连接节点的 `Address:Port`，
  而 hy2 是 QUIC/UDP、不在该端口监听 TCP，必然超时（节点其实可用）。现在 hy2 改走**真实延迟测试**。
- **适配 Xray 新版证书策略**：Xray ≥ 26.1.31 已移除 `tlsSettings.allowInsecure`，带该字段的配置会被内核直接拒绝启动。
  现在不再输出 `allowInsecure`；hy2 的 `pinSHA256` 改为映射到 Xray 的 `pinnedPeerCertSha256`
  （sing-box 只支持公钥 pin，无法识别证书指纹 pin，会忽略该字段）。勾选了"跳过证书校验"但没提供 pin 的节点，
  Xray 下将走严格校验并在启动前提示（可改用 sing-box）。

### v1.3.0

- 新增 **Hysteria2** 节点支持：可解析 `hysteria2://` / `hy2://` 链接与 Clash `type: hysteria2`，
  支持 salamander 混淆、端口跳跃、上下行带宽、`pinSHA256` 证书固定。
  **Xray 与 sing-box 内核可用**（V2Ray 不支持，会在启动前明确提示）；Xray 官方的 Win7 构建也包含 Hysteria 2，
  前提是内核版本够新（官方 v26.3.27 起），旧内核请用「更新内核」升级。

### v1.2.0

- 新增 Xray / V2Ray / sing-box 多内核选择和节点能力预检；Win7 上会阻止使用没有兼容构建的内核。
- 修复 sing-box 1.14 的 `.srs` 规则集下载、检测和规则配置不一致问题。
- 启动时必须确认 SOCKS/HTTP 两个入站均就绪才接管系统代理；端口冲突或内核闪退不再留下无效代理。
- 接管前持久化备份用户原有系统代理/PAC，停止、崩溃或下次启动时安全恢复；不会覆盖其他软件之后做出的修改。
- 订阅拉取与内核下载改为后台执行，避免界面长时间无响应；运行中更新内核成功后自动重连。
- 配置文件改为原子写入并保留备份，损坏时自动恢复；保存失败会显示在日志中。
- “跳过 TLS 校验”改为逐请求生效，避免并发请求意外继承不安全的全局设置。

### v1.1.1

修复：

- **高 DPI 下界面发虚（Win10/11 上尤其明显）**：程序原先没有 Win32 清单，进程是 DPI 无感知的，
  Windows 会把整个窗口当位图放大后交给程序绘制 —— 在 150% 缩放下相当于把 860×600 的画面
  硬拉成 1290×900，必然发糊。现已补齐 `app.manifest`（声明 Per-Monitor v2，Win7 上自动降级为
  系统级感知，不影响兼容性），并按屏幕 DPI 显式放大控件尺寸，避免"字体变大但按钮没变大"的错位。
  实测：150% 缩放下进程 DPI 感知状态由 `UNAWARE`（窗口 DPI 恒报 96）变为
  `PER-MONITOR AWARE`（正确识别 144），窗口由系统拉伸改为程序按 1290×900 原生绘制。

### v1.1.0

修复：

- **安全**：移除全局关闭 TLS 证书校验的行为（旧版会让订阅内容和节点凭据暴露给中间人），
  改为默认严格校验，仅在用户勾选时对单次请求放宽；同时停用已淘汰的 TLS 1.1。
- **直连模式不再空转内核**：旧版选「直连」仍会启动 xray，随后又把系统代理清掉。
- **运行中切换模式立即生效**：旧版只存盘不重启内核，切了模式其实没变。
- **vmess 节点不再被静默丢弃**：订阅里 `"tls": true`（布尔值）会让旧版解析抛异常，
  节点无声消失。
- **传输层协议名归一化**：`websocket` / `http` / `gun` 等别名统一成 xray 认识的
  `ws` / `h2` / `grpc`。
- **Clash 订阅支持 REALITY / gRPC / h2**：旧版读不到 `reality-opts`、`grpc-opts`、
  `h2-opts`、`skip-cert-verify`，这类节点会生成残缺配置。
- **重复导入订阅不再无限追加节点**。
- **内核崩溃时自动撤掉系统代理**，避免断网。
- 打包脚本：修正 `pack.sh` 里的目标框架（net48 → net461）和不存在的 `fetch-core.ps1` 引用；
  CI 产物名不再固定写成 v1.0。

新增：

- 订阅管理（更新 / 编辑 / 删除单个订阅）、批量更新订阅
- 从剪贴板导入、复制节点原始链接、节点去重、清空延迟
- 开机自启、启动时自动连接、导入时自动去重
- 入站嗅探（sniffing）、规则模式国内 DNS、系统代理绕过列表、内核版本显示
- 残留内核进程清理（PID 文件）、端口占用预警
